## 建立 github_action_shell：用 public 仓库驱动私有源 CI

**背景**：私有仓 `edidada/cpp_ecshop`（C++/CMake/vcpkg）的 GitHub Actions 分钟耗尽。
根因是原 CI 矩阵 `macos-latest/ubuntu-latest/windows-latest × crow/httplib` 共 6 job，
macOS 按 10× 计费，估算单次全量 push 约扣 308 分钟，免费 2000 分钟约 7 次即耗尽。

**方案**：Driver/Source 分离 —— `github_action_shell`（public）提供免费 runner，
checkout 私有源执行构建，结果归档回 `results/` 并上传 artifact。

**产出**（全部已 push 到 4 个账号，commit 04c298f）：
- `docs/DESIGN.md` 完整设计方案（含成本测算、合规风险、踩坑记录）
- `.github/workflows/run-source.yml` 三种触发：workflow_dispatch / schedule / repository_dispatch
- `.github/workflows/mirror.yml` 主仓单向镜像到其余 3 账号
- `scripts/` 9 个脚本：discover / run-source / collect-repo-info / gen-report / trigger /
  push-all-remotes / mirror-accounts / bootstrap-accounts / lib.sh
- `config/accounts.env` + `config/sources.env`

**关键设计**：源仓库 owner 用 `github.repository_owner` 自动推导，同一份 workflow 在 4 个账号下
各自拉取自己账号的同名私有仓，解决「同名不同用途」隔离问题。仅主账号跑 schedule 并写归档，
避免多副本同时写 `results/` 造成 git 历史分叉。

**已验证**：脚本语法、workflow YAML、端到端冒烟（discover→run→collect→gen-report）、
真实调用 gh 采集 edidada/cpp_ecshop 信息（分支 crow/main/work、ci #6 failure、8MB、C++）。

## 本机环境踩坑（可复用）

1. **HTTPS push 被代理 502**：本机有 `HTTPS_PROXY=http://127.0.0.1:52236`，git 推 HTTPS 报
   `CONNECT tunnel failed, response 502`；而 `gh` CLI 不受影响（容易误判为权限问题）。
   **解法**：走 `~/.ssh/config` 的 Host 别名 + `Hostname ssh.github.com` `Port 443`。
2. **CRLF 打死 Linux runner**：Windows `core.autocrlf=true` → 加 `.gitattributes` 强制 `*.sh text eol=lf`。
3. **`git add --chmod=+x` 在 Windows 无效**：必须 `git update-index --chmod=+x scripts/*.sh`。
4. **同一 SSH 公钥不能加到多个 GitHub 账号**（Key is already in use），多账号必须各自独立密钥。
